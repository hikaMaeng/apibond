# Test Report: Claude multi-agent bonding

Timestamp: 2026-11-12, Asia/Seoul. Source: `19ce4fa`, runtime 0.1.1.

The original live deployment showed qwen-tuf active=4, qwen-28 active=0 and one session entry. It used only the shared X-Claude-Code-Session-Id; child agent IDs were ignored. Four admissions exhausted that one backend while its peer remained idle. The fix scopes the native Claude fallback to the root session plus agent ID. Explicit APIBond/generic session headers retain precedence and native state-owner checks remain enforced.

## Environment and execution

Windows, installed clauding and Claude Code 2.1.306, two actual LM Studio instances qwen36-35b:28 and qwen36-35b:tuf on port 12345. The isolated workload used port 18181 and capacity four per backend. Production was separately cut over, while idle, to the byte-identical versioned Windows binary on wildcard port 18180 with ten slots per backend. Other user clients/projects were not terminated.

The supplied YouTube webapp task was run twice in separate test directories. Trial 1 confirmed real native agent headers and cross-backend placement, but the model launched only one foreground child. It was explicitly stopped as insufficient parallel-workload evidence. Trial 2 clarified background parallel launch, then observed three primary children and two additional nested children running real tool/file operations. Sanitized request identity and backend headers were correlated with LM Studio server logs and 2-second status samples.

## Routing result

48 requests received HTTP 200: 43 response streams completed and 5 live streams were intentionally cancelled after routing acceptance. No unexpected HTTP/transport failures occurred before cleanup. All six histories retained exactly one backend, including all five actual child agents. Both backends were simultaneously active in 633 status samples; the largest sampled total was 5 in-flight requests.

Thirty status requests during concurrent model inference all returned 200: p50 16.62 ms, p95 17.48 ms, maximum 41.64 ms. This measures local status responsiveness, not pure relay overhead or model generation latency.

After stopping only the isolated test client, both active counters and buffered-body reservations returned to zero. Eight idle session entries remained from the two trials, consistent with the configured one-hour idle TTL. The temporary test listener was then stopped. Production 0.1.1 remains available on port 18180.

LM Studio log correlation: all 48 incoming experiment bodies were matched by the actual Claude session metadata; model qwen36-35b:28 appeared 21 times and qwen36-35b:tuf 27 times, exactly matching the proxy ledger. Other sessions were excluded.

## Checks and limitations

Rust: 25 tests passed, including eight simultaneous Claude agents split 4/4, stable continuations, root namespace separation, explicit-session override and existing native handle/cancellation contracts. Formatting and Clippy passed; three npm installer tests passed. Native Windows fixture smoke passed all six upstream requests. The 0.1.1 release workflow built/tested all five native targets; npm release installation and lazy CLI launch reported apibond 0.1.1. Versioned artifact hashes were checked against canonical staged Git bytes, including LF text normalization.

The real coding workload was explicitly stopped after the routing criteria were met. Its CLI exit 1 is operator cancellation, not successful app completion. Generated frontend/backend/integration files are retained locally; the webapp was not accepted or deployed. Nested-fork denials and missing-file tool errors were observed as model/CLI task behavior and were not counted as relay failures. Separate short nonstreaming probes exhausted max_tokens with no visible text; a 128-token direct LM Studio request produced the same empty-content/max_tokens behavior as the bonded route. Those probes do not establish successful conversation behavior.
