## Failures

- 최초 라우팅 구현의 Clippy 중첩 조건 지적은 같은 조건을 합친 뒤 전체 검수를 다시 통과했다. 실패 로그를 보존했다.
- 입력 구현자의 최초 Node 재현에서 종료 처리 오류가 발생해 하네스를 정리한 후 동일한 기준 코드 관측을 다시 실행했다. 설정 파싱 실패만으로 입력 결함을 재현했다고 주장하지 않았다.
- 독립 HTTP 하네스의 최초 종료 메타데이터가 SIGTERM의 `exitCode=null`을 미종료로 잘못 해석했다. 프로세스 부재를 별도 대조하고 최초 JSON을 보존한 뒤 하네스만 보정해 재실행했다. 최종 `childExited=true`, `childSignalCode=SIGTERM`. 제품 코드와 수용 기준은 변경하지 않았다.
- 최종 제품 검수 실패 또는 미해결 중요 리뷰 지적 없음. 독립 임시 프로세스·listener 잔류0.

## Reproducibility

위 후보에서 명령을 실행한다. 새 회귀는 `tests/json_body_idle.rs`와 `tests/proxy.rs`에 포함돼 있다. 명령별 원본 로그와 독립 하네스는 이슈에 기록된 로컬 검수 증거로 별도 보존하며, 공개 JSON에는 원본 증거 파일의 SHA-256과 필요한 관측값만 담았다.

보고서만 추가한 후속 커밋에서도 `src/`, Cargo 파일, 실행 스크립트 및 두 회귀 테스트의 내용이 후보와 같은지 확인한다. 후속 CI 결과는 이슈 #1에 기록한다.

## Scope and limits

- 이번 네 수정은 source/unreleased 변경이다. 공개 v0.1.1 바이너리·기존 버전 배포물은 교체하지 않았다. 새 JSON 입력 옵션을 기존 바이너리 설정에 추가하면 안 된다.
- 입력 제한은 inspected JSON의 청크 사이 대기에 적용된다. 전체 전송 시간, 추론 시간, raw/multipart 경로의 제한을 바꾸지 않았다.
- backend capacity, upstream timeout 및 ACL 정책은 그대로다. 다른 OS 실행·실모델 멀티모달 추론·수정본 운영 배포의 검증 주장은 하지 않는다.
- 별도 운영 복구 작업에서 사용자 승인 후 기존 0.1.1을 기존 설정으로 기동했다. control API 정상 및 Clauding 채팅의 실제 `CLAUDING_OK` 응답을 확인했으며, 이는 새 후보의 수용 증거와 구분한다.
